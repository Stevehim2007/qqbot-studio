## 2. 新需求（按用户原话整理）

### R1 分群启用插件 + 分群插件参数

按 QQ 群/私聊分别启用或停用插件能力（命令、自然语言、marker 工具、自动回复装饰等），有全局默认、群级覆盖、可能的模板/继承；不能靠“卸载/加载插件”实现（AstrBot 插件加载是全局的），应是运行时能力门控与配置读取。

同时要求**分群插件参数可调**：不只是“这个插件开/关”，而是每个群可以覆盖该插件的可调参数。例如：

- `qqbot_core_reply`：非 @ 参与概率、时间段、回复长度、人格/提示词 profile、是否允许工具。
- `qqbot_safe_tools`：本群允许的工具白名单、冷却、是否需要确认。
- `qqbot_food`：默认城市/位置、搜索条数、排序、是否允许提交评价。
- `qqbot_stickers`：装饰概率、AI 装饰/收藏开关与概率、候选数量。
- `qqbot_memory_commands`：本群是否允许 `/记忆` 写操作、可见 scope、结果条数。

要求：

- 参数 schema 标记 `group_overridable`（是否允许群覆盖）、`group_scope`（group/private/both）、`sensitive`（敏感参数只允许实例管理员改）。
- 优先级明确：实例默认 < 群模板 < 群覆盖；私聊单独覆盖，不继承群配置。安全/密钥/全局资源类参数不允许群覆盖。
- 运行时按 `plugin_id + group_id + revision` 读取快照；配置变更原子提交、缓存失效、可回滚。
- Studio 群策略面板按插件分组展示“启用 + 参数覆盖”，只显示允许覆盖的字段；不允许的字段显示“继承全局”。
- 所有覆盖写入审计日志（谁、哪个群、旧值/新值），但不得记录密钥。

### R2 见人说人话（按历史对话调节表达）

基于历史对话/记忆，为不同群、不同用户、不同关系调整称呼、语气、长度、梗密度、话题边界；需要可解释、可关闭、防止被对话内容“投毒”带偏；涉及 LLM 总结与存储成本。

### R3 情绪系统 + 非 @ 概率接话 + 上下文插话判定

- 情绪状态（至少 valence/arousal 或自定义维度）：按群/人格维护，事件触发、随时间衰减、影响回复。
- 非 @ 消息不再只靠固定概率：概率接话 + “上下文是否值得插话”的判定（规则/轻量分类/LLM 预算），避免打断、重复、自说自话。
- 必须保持唯一聊天模型入口与 turn 预算，不能引入第二个模型控制器或无限续轮。

### R4 自定义时间段概率（删除消息段）

- 按时间段/星期配置非 @ 回复概率（例如白天低、晚上高；工作日/周末不同），支持多个自定义时间窗、跨午夜、IANA 时区、群级独立时间窗/概率覆盖。
- **明确删除“消息段”功能**：不做回复拆分、段级延迟、段级投递账本、失败分段重发；一条回复仍按现有单条消息/媒体链路发送。用户已确认“消息段”是写错了，下一版只保留时间段可自定义。

### R5 好感度插件

按群/人格记录用户好感度；说政治敏感话题、辱骂机器人等行为降低好感度；高/低好感度影响语气、称呼、是否接话、可用工具等；需要阈值、冷却、误判申诉/重置、隐私边界。

### R6 关系网插件

记录群友之间的关系网（节点=成员，边=关系类型/强度/证据/时间），从对话中抽取或手动维护；按群隔离；支持查询/可视化摘要；需要考虑隐私、误判、数据生命周期。

### R7 词汇库插件

收录流行词、缩写、梗及其含义/用法/例句；支持逐步添加、编辑、导入导出、去重、启停；注入 AstrBot 知识库（或等价检索层），在回复上下文中按预算注入；注意提示注入与内容安全。

### R8 记忆系统更新（承接上一轮）

已具备：`qqbot_memory_commands` 4.0（五 scope、会话/人格管理、provider/store）、direct/astrbot 记忆模式、Studio 记忆管理 API 与策略面板、记忆内容导入/导出/反思（见 `docs/memory-management-plan.md`、`memory-policy.md`、`memory-admin-api.md`）。

新需求要求评估并扩展：
- 五 scope 是否覆盖“群/用户/关系/人格/全局”新数据；
- 情绪、好感度、关系网、风格画像、词汇库分别属于记忆服务还是独立插件单写；
- 统一授权、清空/导出/保留策略、跨会话一致性；
- 与 Studio 管理面板/控制桥的读写路径。

## 3. 架构约束（必须遵守）

- 单写者：每类数据只有一个 owner；跨插件通过 ABI v1 provider/服务调用，不直接写别人 DB。
- 单回复 owner：`qqbot_core_reply` 仍是唯一聊天控制器；safe_tools 仍是唯一 marker 解析/授权/调度者。
- 新插件遵循 `qqbot-plugins` 标准：stdlib-only、`metadata.yaml`、`_conf_schema.json`、`VERSION`、`main.py`、`tests/`，不 import 旧插件。
- 配置/数据/会话/记忆升级必须可迁移、可回滚、可审计；敏感信息不入日志。
- 群级隔离与隐私：关系网/好感度/风格画像按群（或明确 scope）隔离；支持关闭与删除。
- 测试：每阶段目标测试 + 最终全量；框架需给出测试矩阵与 E2E 场景。

## 6. 补充：学习 SurfCore 的记忆设计

只学习设计，不复制代码，也不把 SurfCore 作为运行时依赖。

需要纳入评估：

- 衰减记忆卡：清晰度、遗忘、容量告警、压缩；只把活跃记忆注入提示词。
- 全量记忆卡：append-only 存档，不全部注入，按需检索。
- 记忆分层：重要事实、关系状态、未完成话题、情绪/事件、长期画像。
- 检索排序：相关度、重要性、新近度、关系权重、未完成话题权重。
- 会话收尾：回复后生成摘要、判断是否结束、留下下次可接的话题。
- 主动目的：从近期记忆提炼“想弄明白/想做”的目的，受时间、冷却、额度和用户边界限制。
- 人格/关系绑定：同一记忆在不同人格/关系中可读取的范围不同，不能跨群/跨用户串记忆。
- 记忆预算：限制注入条数、字符数、摘要长度和刷新频率，避免 token 失控。

要求框架明确：

```text

哪些属于关系网/好感度/情绪/词汇库独立插件
```

## 9. 补充：人格与上下文的成本优化

下一版框架必须纳入，不得每轮重新注入完整人格/历史：

### 9.1 人格分层

```text
persona_core    200-400 字，常驻，稳定可缓存
persona_style   语气、口癖、称呼，按需注入
persona_lore    背景故事，只在相关话题检索
persona_rules   安全/边界规则，短且稳定
```

完整人格存人格库/长期记忆，不默认塞入每轮 prompt。

### 9.2 稳定前缀与缓存

- 人格和固定规则放在 prompt 前缀；
- 前缀中不得放时间戳、随机数、实时状态等变化内容；
- 同一会话尽量复用同一 provider；
- 支持 provider prompt caching 时必须利用；
- `qqbot_core_reply` 按 `persona_id + revision + platform + bot_id` 缓存渲染结果；
- 人格切换或修改才失效。

### 9.3 上下文压缩

```text
固定规则/人格核心
+ 会话阶段摘要（低频更新）
+ 按需检索的记忆卡
+ 最近 N 条原始消息
+ 当前用户消息
```

不要每轮把完整历史、完整人格、全部记忆重新拼接。

### 9.4 记忆与人格分离

- 人格是稳定、短、可缓存；
- 记忆是动态、按 scope 检索；
- 关系/情绪是短状态，变化时更新；
- 禁止将关系网、所有用户记忆、所有群记忆无条件拼入 prompt。

### 9.5 可观测性

框架需给出：

```text
persona_cache_hit / miss
rendered_persona_chars
prompt_prefix_chars
history_messages
retrieved_memory_items
estimated_input_tokens
```

并在 Studio 中展示，便于判断是否还在重复烧人格。

### 9.6 验收

- 同一人格连续 10 轮对话，人格渲染不重复计算；
- 人格未变化时前缀字节级稳定；
- 人格切换后缓存失效且新人格立即生效；
- 长会话不会无限增长 prompt；
- 记忆检索条数和字符数有硬预算；
- provider 不支持缓存时有降级策略。
