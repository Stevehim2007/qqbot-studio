# 下一大版本：8 项拍板与设计解释

> 状态：已拍板，作为 `docs/next-major-brief.md` §10 与 `workbuddy-local/next-major-framework.md` r6 的权威口径。
> 本文只解释设计与边界，不声称功能已实现。

## 1. 插件拆分：2 个业务状态插件 + 1 个词汇库

**结论：可以，按“好感 + 关系”一个、“情绪 + 风格”一个来做。**

| 插件 | 负责 | 不负责 |
|---|---|---|
| `qqbot_social_state` | 好感度、关系网；按 `(group, persona, actor)` 隔离；规则事件、冷却、日上限、衰减、证据哈希 | 情绪、风格、词汇、聊天、marker、模型调用 |
| `qqbot_expression_state` | 情绪（valence/arousal）、风格画像（有界维度/置信度/刷新）；按 `(group, persona)` 隔离；读时衰减 | 好感、关系、词汇、聊天、marker、模型调用 |
| `qqbot_vocabulary` | 词汇条目、别名、含义、用法、例句、导入导出、去重、启停、检索注入 | 聊天、记忆、社交状态、直接改 AstrBot 知识库 |

为什么不是四个插件：情绪/风格共享 `(group, persona)` 读时衰减和一次 prompt 读取；好感/关系共享 `(group, persona, actor)` 复合键、证据/衰减/隐私/导出。拆成四个会让每次回复多出多次跨插件调用和多套配置/面板，而 single-writer 仍然可以由两个插件各自保证。词汇库生命周期不同，必须独立。

## 2. “侧车”（sidecar）是什么

侧车不是第二个机器人，也不是让 AstrBot 再跑一个进程。它是**贴在 AstrBot 旁边的独立策略存储**：

```text
AstrBot 插件（core_reply / food / stickers ...）
        │  只读生效快照
        ▼
qqbot_safe_tools  ──单写──►  capability_policy.json（侧车）
        ▲                         │
        └──── Studio 控制桥 ◄─────┘
```

- `qqbot_safe_tools` 是唯一写者；其他插件只读 `policy_effective` 快照，不直接改文件。
- Studio 通过控制桥读取/修改/重置；变更带 revision，热更新失败时保留旧快照并报错。
- 群管理员开关：`group_admin_override_enabled`，**默认关闭**。开启后群主/管理员只能改本群允许覆盖的非敏感参数（如回复概率、时间段、装饰概率），不能查看、导出、删除任何数据，也不能放宽全局安全 allowlist。

## 3. “首版”和辅助 LLM 预算

**首版 = 下一大版本的第一个正式测试版本**，不是每个小修都重新定义。

- 辅助 LLM 月预算：**10–20 元人民币**，只用于可选的后台摘要、抽取、风格刷新、插话灰区判定等。
- 规则优先：能用规则/词典/统计解决的，不调用 LLM。
- 80% 预算预警，100% 停止可选调用；核心聊天、命令、工具执行不依赖辅助 LLM。
- 预算按实例统计，不按群分摊；超限只降级辅助能力，不影响主回复。

## 4. 可见性与删除权

**结论：只在 Studio 控制台。**

- 好感、关系、情绪、风格、记忆卡片的查看、导出、删除、重置，全部在 Studio 的对应面板/API。
- QQ 内不提供数据查询/删除命令；群管理员只能改参数，不能看数据。
- 删除默认按当前实例/当前群范围执行；跨群删除必须由实例管理员在 Studio 显式选择。
- 用户申诉入口可以保留为“提交理由”，但不返回分数/关系明细。

## 5. 五 scope 与可选第六 scope

当前五 scope：`group / user / conversation / persona / global`，保持不变。

`group_member` 是**可选第六 scope**，用于“同一群内某个成员”的长期画像/关系事实：

- 默认不启用、不迁移、不写入；
- 按群显式开启；
- 开启后仍受群隔离与 Studio 删除权约束；
- 不改变现有五 scope 的 ABI；老数据不需要重写。

两者的区别：五 scope 是现有稳定契约；`group_member` 是把“群内成员”从 `user`（跨群）里细分出来，避免把 A 群的关系带到 B 群。

## 6. 词汇库接 AstrBot 知识库

**结论：接知识库，但 `qqbot_vocabulary` 仍是条目唯一 owner。**

```text
qqbot_vocabulary（SQLite，真源）
   ├─ 条目/别名/含义/用法/例句/启用状态
   ├─ 导出到 AstrBot 知识库（索引/检索）
   └─ 本地 SQLite+FTS 作为离线回退
```

- 知识库负责检索/索引，不产生第二份可编辑真源。
- 注入时按预算取 Top-K，附来源与更新时间；不把整库塞进 prompt。
- 删除/停用条目时同步删除/失效知识库文档；失败则标记待清理，不静默留下脏索引。

## 7. 测试版统一先开与“灰度”

测试版策略：**全部新能力先开，但带总开关、保守预算、频率上限和回滚开关**。这样能一次看到真实交互，而不是逐个猜测。

“灰度”不是“全量直接开”，而是：

1. 先选 1 个隔离实例/测试群；
2. 按群或按比例放量（例如 10% → 50% → 100%）；
3. 观察回复质量、延迟、成本、误判、隐私投诉；
4. 指标异常立即按群关闭/回滚；
5. 生产 `bot-1` 默认关闭或只开低风险项，直到测试版验证完成。

各能力作用：情绪影响语气/接话乘子；好感影响称呼/边界/工具可用性；关系影响称呼与话题；风格影响长度/梗密度；词汇库影响用词与梗解释；记忆卡片影响长期连续性；人格分层影响稳定人设与成本。

## 8. 人格四层 vs 现有 `group_personas` / `prompt_profiles`

两者不是同一个东西：

| | 现有 `group_personas` / `prompt_profiles` | 新人格四层库 |
|---|---|---|
| 形态 | 一段/多段 prompt 文本 + 选择/绑定 | `core / style / lore / rules` 结构化四层 + revision |
| 用途 | 当前聊天的人格文本 | 稳定前缀、可缓存、可分层裁剪、可审计 |
| 记忆 | 可能混在 prompt 里 | `persona` scope 只存“与人格绑定的记忆”，不存人格定义 |
| 迁移 | 作为迁移来源/兼容层 | 新库为权威；旧 profile 可映射为 core/style 初稿 |

建议：新库为权威；旧 `group_personas`/`prompt_profiles` 继续可读，作为兼容层；迁移时先生成草稿，人工确认后启用。`lore` 放人格库（按需检索），不塞进常驻前缀；`rules` 是硬约束，优先级最高。

## 9. 已删除的“消息段”

已从 brief/framework 删除回复拆分、段间延迟、段级账本、失败分段重发；只保留**自定义时间段概率**（多时间窗、时区、跨午夜、群级覆盖）。失败或 `outcome_unknown` 不重发，避免刷屏和重复。
